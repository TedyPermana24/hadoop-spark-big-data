2	Latihan Laboratorium (Lab Exercise)
Pada latihan ini, sistem komputasi terdistribusi Hadoop Distributed File System (HDFS) dan Hadoop MapReduce dijalankan menggunakan lingkungan kontainer Docker. Komponen yang digunakan meliputi NameNode sebagai pengelola metadata kluster dan DataNode sebagai penyimpan fisik blok data. Penggunaan Docker memudahkan proses deployment dan isolasi lingkungan kluster terdistribusi, sehingga pengujian sistem berkas terdistribusi dan eksekusi komputasi paralel dapat langsung dilakukan.
[Gambar memperlihatkan docker container]
Pada tahap awal pengujian HDFS, layanan sistem berkas terdistribusi dipastikan telah aktif pada kluster. Pengujian dilakukan dengan membuat direktori baru pada HDFS bernama /user/student menggunakan perintah hdfs dfs -mkdir. Selanjutnya, disiapkan berkas teks lokal bernama sample.txt yang berisi paragraf mengenai ekosistem Big Data Hadoop dan Spark, serta berkas log dan relasi data pasien yang kemudian dimasukkan ke dalam direktori HDFS tersebut menggunakan perintah hdfs dfs -put.
Untuk memastikan bahwa seluruh berkas telah berhasil diterima dan tersimpan di dalam HDFS, dilakukan pengecekan daftar berkas menggunakan perintah hdfs dfs -ls serta menampilkan isi teks dari berkas tersebut secara langsung dari HDFS menggunakan perintah hdfs dfs -cat.
[Gambar memperlihatkan eksekusi perintah hdfs dfs -mkdir, -put, -ls, dan -cat pada terminal]
Berdasarkan hasil eksekusi perintah tersebut, direktori /user/student berhasil dibuat dan berkas teks telah tersimpan di dalam HDFS serta isi teksnya dapat ditampilkan dengan tepat. Hasil penyimpanan berkas di HDFS juga divalidasi secara visual melalui antarmuka web Hadoop NameNode (Web UI).
[Gambar memperlihatkan browse directory HDFS /user/student pada Web UI]
Dalam arsitektur Hadoop MapReduce, aliran pemrosesan data mengikuti tahapan Input Splits, Map, Shuffle & Sort, dan Reduce. Pada tahap Map, data masukan dipecah menjadi baris-baris teks dan dipetakan menjadi pasangan kunci-nilai perantara (intermediate key-value pairs). Sebelum ditransfer melalui jaringan, diterapkan fungsi Combiner sebagai mini-reducer lokal pada setiap DataNode untuk mereduksi volume data intermediate. Pada fase Shuffle & Sort, pasangan kunci-nilai dikelompokkan dan diurutkan berdasarkan kunci. Mekanisme Partitioner (HashPartitioner default: (key.hashCode() & Integer.MAX_VALUE) % numReduceTasks) memastikan seluruh data yang memiliki kunci yang sama dialirkan ke node Reducer yang tepat, sehingga proses agregasi global pada fungsi Reduce berjalan secara konsisten.
[Gambar memperlihatkan diagram alur MapReduce Data Flow]
Tahapan berikutnya adalah pengujian komputasi Word Count menggunakan program MapReduce. Program membaca berkas teks masukan dari HDFS, memecah kalimat menjadi token kata, mengelompokkannya pada fase Shuffle & Sort, dan menjumlahkan total frekuensi kemunculan setiap kata unik menggunakan fungsi Reducer. [Gambar output hasil eksekusi Word Count pada terminal]
Berdasarkan hasil pengujian Word Count, kata "data" muncul dengan frekuensi tertinggi sebanyak 4 kali, disusul oleh "big", "hadoop", "spark", dan "is" masing-masing sebanyak 3 kali, membuktikan bahwa komputasi pemetaan dan pereduksian terdistribusi berjalan dengan tepat.
Selain Word Count, dilakukan pula pengujian terhadap dua pola permasalahan Big Data lainnya: Log Analysis dan Reduce-Side Join. Log Analysis memproses berkas log server (server_logs.txt) untuk mengekstrak frekuensi kode status HTTP dan log level, menghasilkan 7 permintaan sukses (HTTP_200: 7), 2 berkas tidak ditemukan (HTTP_404: 2), 3 galat server (HTTP_500: 3), serta sebaran log level operasional. Sementara itu, Reduce-Side Join berhasil memadukan data demografi pasien (patients_info.txt) dengan data rekam diagnosa (patients_diagnosis.txt) berdasarkan foreign key patient_id secara terdistribusi.

3	Studi Kasus Kesehatan (Health Informatics Case Study)
Rumah Sakit mengelola data pasien dalam skala besar yang mencakup puluhan ribu rekam medis elektronik (Electronic Health Records / EHR). Untuk memenuhi kebutuhan analitik klinis terdistribusi, pemetaan faktor risiko epidemiologi, dan pemantauan beban penyakit kronis, diterapkan arsitektur pemrosesan Big Data modern:
1.	Hadoop Distributed File System (HDFS) untuk penyimpanan terdistribusi data historis rekam medis pasien berskala besar yang aman dan toleran terhadap kegagalan perangkat keras.
2.	Hadoop MapReduce Engine untuk komputasi analitik batch berskala masif secara terdistribusi dan efisien melalui optimasi Combiner lokal.
3.	Serving Layer Dashboard untuk menyajikan visualisasi ringkasan indikator klinis, metrik regional, serta profil hemodinamik pasien bagi dokter dan manajemen rumah sakit.
3.1	Menyiapkan dan Menyimpan Data EHR Lengkap ke HDFS
Tahap pertama adalah menyiapkan dataset rekam medis lengkap (full_dataset_ehr.csv) yang memuat 10.000 riwayat pasien. Data berisi patient_id, usia, jenis kelamin, etnis, wilayah domisili (North, South, East, West, Central), diagnosis penyakit kronis (Coronary Artery Disease, Type 2 Diabetes, Hypertension, Chronic Kidney Disease, Lung Cancer, dan lain-lain), derajat keparahan (Severe, Moderate, Mild), obat-obatan, jumlah kunjungan, tekanan darah sistolik dan diastolik, detak jantung, kolesterol, indeks massa tubuh (BMI), serta status luaran pasien (adverse_outcome). Data tersebut kemudian disimpan pada HDFS di direktori '/hospital/mapreduce/full_dataset_ehr.csv' agar dapat diproses oleh kluster MapReduce. Pasien dikategorikan berisiko tinggi apabila memiliki tekanan darah sistolik >= 140 mmHg, atau kadar kolesterol >= 240 mg/dL, atau berusia >= 60 tahun.
[Gambar browse directory HDFS /hospital/mapreduce pada Web UI]

3.2	Job 1: Analisis Sebaran Pasien Berisiko Tinggi per Wilayah
Tahap ini bertujuan memetakan konsentrasi pasien berisiko tinggi di setiap wilayah geografis guna membantu rumah sakit dalam perencanaan alokasi sumber daya medis dan zonasi intervensi kesehatan. Program Mapper memfilter kriteria klinis dan memancarkan nama wilayah beserta nilai 1. Combiner diterapkan secara lokal pada setiap DataNode untuk menjumlahkan frekuensi per wilayah sebelum data ditransfer melewati jaringan kluster pada tahap Shuffle & Sort, meminimalkan penggunaan bandwidth jaringan. Reducer kemudian mengakumulasi total pasien berisiko tinggi per wilayah.
[Gambar output hasil eksekusi Job 1 pada terminal]
Berdasarkan hasil analisis Job 1, dari total 10.000 pasien teridentifikasi sebanyak 6.508 pasien (65,08%) berada dalam kategori risiko tinggi. Wilayah North mencatat jumlah pasien risiko tinggi terbanyak yaitu 1.341 pasien (20,61%), disusul wilayah South dengan 1.314 pasien (20,19%), Central dengan 1.304 pasien (20,04%), West dengan 1.298 pasien (19,94%), dan East dengan 1.251 pasien (19,22%).

3.3	Job 2: Analisis Luaran Klinis yang Merugikan (Adverse Outcome Rate) per Penyakit
Tahap ini menganalisis proporsi kejadian luaran buruk klinis dan komplikasi fatal (adverse outcome rate) pada setiap diagnosis penyakit kronis. Program Mapper memancarkan nama diagnosis sebagai kunci dan nilai adverse flag, sedangkan Reducer menghitung total pasien serta total kejadian luaran buruk untuk mengkalkulasi persentase akhir.
[Gambar output hasil eksekusi Job 2 pada terminal]
Hasil pengujian menunjukkan bahwa Coronary Artery Disease (CAD) memiliki tingkat adverse outcome tertinggi sebesar 42,56% (512 kasus dari 1.203 pasien), diikuti oleh Chronic Kidney Disease (CKD) sebesar 41,97% (515 kasus dari 1.227 pasien), Lung Cancer sebesar 38,02% (452 kasus dari 1.189 pasien), dan Type 2 Diabetes sebesar 37,90% (465 kasus dari 1.227 pasien). Hasil ini memberikan peringatan klinis bahwa kelompok penyakit kardiovaskular dan ginjal memerlukan perhatian penanganan yang paling intensif.

3.4	Job 3: Pemetaan Profil Tekanan Darah Sistolik Berdasarkan Diagnosis dan Keparahan
Tahap ini melakukan pemetaan komprehensif terhadap rata-rata (mean) tekanan darah sistolik pasien berdasarkan kombinasi diagnosis penyakit dan derajat keparahan (Severe, Moderate, Mild) menggunakan composite key. Reducer mengagregasi total tekanan darah dan membaginya dengan jumlah pasien pada masing-masing sub-kategori keparahan.
[Gambar output hasil eksekusi Job 3 pada terminal]
Hasil analisis membuktikan bahwa rata-rata tekanan darah sistolik tertinggi terpusat pada kategori Severe penyakit kardiovaskular dan ginjal: Coronary Artery Disease Severe sebesar 164,63 mmHg (215 pasien), Hypertension Severe sebesar 164,15 mmHg (210 pasien), dan Chronic Kidney Disease Severe sebesar 163,90 mmHg (227 pasien). Seluruh nilai ini berada jauh di atas ambang krisis hipertensi derajat 2 (>160 mmHg) yang secara patofisiologis meningkatkan risiko serangan jantung dan stroke.

3.5	Menampilkan Hasil melalui Serving Dashboard Terpadu
Seluruh hasil pemrosesan analitik batch MapReduce disajikan melalui antarmuka web terpadu pada Serving Layer di URL http://localhost:5000/mapreduce (atau http://localhost:5015/mapreduce) dan REST API pada http://localhost:5000/api/mapreduce_results (atau http://localhost:5015/api/mapreduce_results). Halaman MapReduce Analytics menyajikan:
1.	Kartu indikator kinerja utama (KPI) pasien risiko tinggi (6.508 pasien), penyakit dengan luaran buruk tertinggi (CAD 42,56%), dan rekor rata-rata tekanan darah sistolik (164,63 mmHg).
2.	Diagram alur 4 tahap komputasi MapReduce (Map, Combiner, Shuffle & Sort, Reduce).
3.	Panel visualisasi kartu metrik dan proporsi sebaran pasien berisiko tinggi untuk 5 wilayah geografis.
4.	Tabel analitik komparatif tingkat adverse outcome penyakit dengan indikator warna urgensi klinis.
5.	Tabel interaktif penjelajah profil tekanan darah sistolik berdasarkan diagnosis dan tingkat keparahan.
[Gambar antarmuka web MapReduce Analytics pada Serving Dashboard]
