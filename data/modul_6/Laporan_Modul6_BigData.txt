1	Pendahuluan
Modul ini membahas dasar-dasar pemrosesan data terdistribusi berskala besar menggunakan kerangka kerja Apache Spark (PySpark). Pembahasan mencakup arsitektur inti Spark yang terdiri dari Driver Program, Cluster Manager, dan Executors, keunggulan komputasi dalam memori (in-memory computation) Spark dibandingkan dengan Hadoop MapReduce berbasis disk, abstraksi data RDD (Resilient Distributed Dataset) dan DataFrame yang dioptimalkan oleh Catalyst Optimizer, serta mekanisme eksekusi evaluasi malas (lazy evaluation) berbasis Directed Acyclic Graph (DAG). Pengujian laboratorium dilakukan melalui operasi dasar RDD dari koleksi data, pembuatan DataFrame dari berkas CSV, eksekusi kueri Spark SQL, serta penghitungan kata terdistribusi (Word Count RDD). Selanjutnya, seluruh konsep tersebut diimplementasikan ke dalam studi kasus kesehatan analisis teks laporan biopsi patologi kanker dan metadata rekam medis pasien (EHR) secara terdistribusi yang terintegrasi langsung dengan antarmuka web Serving Dashboard.

Arsitektur Apache Spark bekerja dengan memisahkan peran antara Driver Program, Cluster Manager, dan Executors. Driver Program berfungsi mengoordinasikan eksekusi aplikasi, mendefinisikan transformasi data, dan menyusun Directed Acyclic Graph (DAG) tugas komputasi. Cluster Manager (Standalone Manager pada port 8080 atau YARN) bertanggung jawab mengalokasikan alokasi CPU core dan memori RAM pada simpul pekerja. Selanjutnya, Executors mengeksekusi tahapan tugas (tasks) secara paralel di dalam memori RAM tanpa melakukan penulisan berulang ke media penyimpanan fisik disk.

[Gambar memperlihatkan diagram alur arsitektur Apache Spark]

Tahapan berikutnya adalah perancangan dan eksekusi program PySpark dasar yang mencakup:
1.	Operasi RDD dari Koleksi List: Menginisialisasi RDD menggunakan sc.parallelize([1, 2, 3, 4, 5]) dan melakukan aksi rdd.reduce(lambda a, b: a + b) untuk menjumlahkan seluruh elemen secara paralel.
2.	Pembuatan DataFrame dari Berkas CSV: Membaca berkas data.csv menggunakan spark.read.csv() dengan inferSchema=True dan header=True, kemudian menampilkan struktur skema dan 5 baris pertama data melalui df.show(5).
3.	Eksekusi Spark SQL: Mendaftarkan DataFrame sebagai temporary view bernama people melalui df.createOrReplaceTempView("people"), kemudian menjalankan kueri spark.sql("SELECT name, age FROM people WHERE age > 30") untuk memfilter rekaman individu berusia di atas 30 tahun.
4.	Word Count Menggunakan RDD: Membaca berkas sample.txt menjadi RDD teks, menerapkan transformasi flatMap() untuk memecah baris menjadi kata, map() untuk menghasilkan pasangan (kata, 1), serta reduceByKey() untuk mengagregasi frekuensi kemunculan setiap kata.

3	Studi Kasus Kesehatan (Health Informatics Case Study)
Lembaga riset onkologi dan rumah sakit memerlukan sistem analitik terdistribusi berkecepatan tinggi untuk memproses laporan biopsi patologi kanker paru (unstructured text) dan memadukannya dengan metadata rekam medis pasien (structured data) guna membantu deteksi dini keganasan serta mempercepat alokasi tindakan klinis. Untuk memenuhi kebutuhan tersebut, diterapkan arsitektur pemrosesan Big Data modern:
1.	Hadoop Distributed File System (HDFS) untuk penyimpanan terdistribusi data rekam medis pasien dan arsip laporan patologi.
2.	Apache Spark Engine untuk pemrosesan paralel teks tidak terstruktur berbasis RDD dan analisis terstruktur berbasis Catalyst DataFrame & Spark SQL secara in-memory.
3.	Serving Layer Dashboard untuk menyajikan visualisasi ringkasan pola patologi, stratifikasi kohort kanker, dan perbandingan performa sistem bagi klinisi.

1.	Menyiapkan dan Menyimpan Data Patologi dan Rekam Medis ke HDFS
Tahap pertama adalah menyiapkan berkas laporan biopsi patologi (pathology_notes.txt) yang memuat catatan histopatologi jaringan paru pasien, serta dataset rekam medis lengkap (full_dataset_ehr.csv) yang memuat 10.000 riwayat pasien dengan 20 atribut klinis. Kedua berkas tersebut diunggah dan disimpan ke repositori HDFS pada direktori '/hospital/spark/'.

[Gambar browse directory HDFS /hospital/spark pada Web UI]

2.	Analisis Teks Tidak Terstruktur (Laporan Biopsi Patologi) Menggunakan RDD
Tahap ini bertujuan mendeteksi indikator lesi ganas dan karakteristik histologis dari laporan biopsi jaringan paru. Skrip PySpark membaca pathology_notes.txt ke dalam RDD, melakukan tokenisasi kata, membersihkan tanda baca, dan memfilter kata kunci patologi kritis (malignant, adenocarcinoma, carcinoma, suspicious, metastatic, necrosis, invasion, neoplasm, benign). Menggunakan rantai transformasi flatMap(), map(), dan reduceByKey(), sistem mengekstrak frekuensi pola patologi secara paralel.

[Gambar output hasil eksekusi ekstraksi pola patologi RDD pada terminal]

Berdasarkan hasil analisis RDD, dari total 20 laporan patologi yang diproses, sebanyak 16 laporan (80,0%) terdeteksi menunjukkan indikasi keganasan atau lesi mencurigakan (malignant/suspicious). Kata kunci yang paling sering muncul adalah "malignant" (9 kali), "carcinoma" (7 kali), "adenocarcinoma" (6 kali), "benign" (6 kali), "neoplasm" (4 kali), dan "suspicious" (4 kali). Ekstraksi otomatis ini mempercepat proses triase laporan laboratorium patologi anatomi.

3.	Analisis Data Terstruktur Metadata Pasien Kanker Menggunakan Spark DataFrame & SQL
Tahap ini melakukan analisis mendalam terhadap sub-populasi 1.189 pasien kanker paru (Lung Cancer) dari dataset 10.000 EHR menggunakan Spark DataFrame dan Spark SQL yang dioptimalkan oleh Catalyst Optimizer. Kueri mengelompokkan data berdasarkan derajat keparahan (Severe, Moderate, Mild) untuk mengalkulasi total pasien, rata-rata tekanan darah sistolik, rata-rata kolesterol, jumlah kasus luaran buruk, dan persentase adverse outcome rate.

[Gambar output hasil kueri analitik kohort kanker pada terminal]

Hasil kueri Spark SQL menunjukkan bahwa kohort Lung Cancer terdiri dari 224 pasien Severe, 433 pasien Moderate, dan 532 pasien Mild. Pasien kategori Severe mencatat rata-rata tekanan darah sistolik tertinggi sebesar 142,73 mmHg dan adverse outcome rate tertinggi sebesar 50,45% (113 kasus). Sementara itu, kategori Moderate mencatat adverse outcome rate 39,26% (170 kasus) dan kategori Mild mencatat 31,77% (169 kasus). Secara keseluruhan, tercatat 452 kasus luaran buruk dari 1.189 pasien (adverse rate rata-rata 38,02%).

4.	Benchmark Kecepatan Pemrosesan: Apache Spark vs Hadoop MapReduce
Tahap ini membandingkan latensi pemrosesan data antara kerangka kerja Apache Spark (komputasi in-memory RDD/Catalyst) dengan Hadoop MapReduce (pemrosesan disk-based Map, Spill, dan Shuffle) pada volume data 10.000 rekam medis.

[Gambar output perbandingan performa latensi eksekusi Spark vs MapReduce pada terminal]

Hasil pengujian membuktikan bahwa eksekusi agregasi pada Hadoop MapReduce membutuhkan waktu rata-rata 4.465,28 ms karena harus melakukan penulisan berkas sementara (spill) ke disk fisik pada setiap pergantian tahap. Sebaliknya, Apache Spark menyelesaikan komputasi yang setara hanya dalam waktu 97,68 ms karena seluruh operasi transformasi RDD dan DataFrame diproses secara langsung di dalam memori RAM. Hal ini membuktikan bahwa Apache Spark menghasilkan peningkatan kecepatan komputasi (speedup factor) sebesar 45,71 kali lebih cepat dibandingkan Hadoop MapReduce.

5.	Menampilkan Hasil melalui Serving Dashboard Terpadu
Seluruh hasil pemrosesan analitik patologi dan benchmark kecepatan Spark diintegrasikan ke dalam antarmuka web dashboard klinisi pada URL http://localhost:5000/spark (atau http://localhost:5015/spark) serta REST API pada endpoint http://localhost:5000/api/spark_cancer_analytics (atau http://localhost:5015/api/spark_cancer_analytics). Halaman Spark Analytics menyajikan:
1.	Kartu indikator kinerja utama (KPI) klinis (1.189 pasien kanker paru teranalisis, 80,0% tingkat deteksi patologi keganasan, dan akselerasi performa 45,71x lebih cepat).
2.	Diagram komponen arsitektur Apache Spark (Driver, Standalone Cluster Manager, dan Executors).
3.	Tabel visualisasi hasil ekstraksi RDD terhadap pola kata kunci patologi beserta signifikansi klinisnya.
4.	Tabel komparatif kohort kanker paru Spark SQL berdasarkan tingkat keparahan (Severe, Moderate, Mild).
5.	Panel komparasi performa latensi eksekusi Apache Spark In-Memory vs Hadoop MapReduce Disk I/O.
